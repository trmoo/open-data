# 공공데이터 수집 기록장

고등학교 **「데이터 과학」** 수업용 웹앱입니다.
학생이 공공·민간 데이터 사이트에서 데이터를 하나 찾아, **수집한 데이터의 기본 정보 여덟 가지**를
기록장에 적고 제출합니다. 제출한 내용은 **선생님의 구글 스프레드시트에 학생 1명 = 1줄**로 쌓입니다.

> 성취기준 **[12데과02-01]** 데이터를 편향되지 않도록 수집하고, 수집된 데이터의 특성을 분석한다.
> 연계 [12데과01-02] 정형·비정형 구분과 속성별 의미 / [12정02-03] 문제 해결에 적합한 데이터 수집

## 설치 (선생님이 한 번만)

1. 구글 드라이브에서 **스프레드시트를 새로 만듭니다.** 이름은 아무렇게나 (예: 「데이터 수집 기록장 2학년」).
2. 그 시트에서 **확장 프로그램 → Apps Script** 를 누릅니다.
3. 편집기 왼쪽 ⚙️ **프로젝트 설정** → 「`appsscript.json` 매니페스트 파일을 편집기에서 표시」를 **켭니다.**
4. `src/` 의 파일 열 개를 **하나씩 만들어 그대로 붙여넣습니다.**
   - `.gs` 는 [＋] → 스크립트, `.html` 은 [＋] → HTML 로 만듭니다.
   - 파일 이름에서 **확장자는 뺍니다** (`index`, `css`, `s1` …). 편집기가 붙여 줍니다.
   - 처음부터 있는 `Code.gs` 는 내용만 바꿔 붙여넣으면 됩니다.
   - `npm run pack` 을 돌리면 `dist/appsscript/` 에 붙여넣을 파일과 순서 안내가 만들어집니다.
5. 저장(Ctrl+S)한 뒤 **스프레드시트로 돌아가 새로 고침**합니다.
   위쪽에 **[공공데이터 수집 기록장]** 메뉴가 생깁니다.
6. 메뉴 → **① 시트 준비하기** 를 한 번 실행합니다. (권한 승인 창이 뜨면 허용)
7. 편집기에서 **배포 → 새 배포 → 유형 「웹 앱」**
   - 실행 대상: **나**
   - 액세스 권한: **모든 사용자** (학생이 구글 로그인 없이 들어올 수 있게)
   - 나오는 주소를 학생에게 알려 줍니다.

> **고친 뒤 다시 배포할 때는 「새 배포」가 아니라 [배포 관리] → 연필(수정) → 버전 「새 버전」 → 배포.**
> 새 배포를 만들면 **주소가 바뀝니다.**

## 학생에게 알려 줄 것 (3줄)

1. 주소를 열고 **학번**을 넣습니다. 처음이면 이름과 비밀번호를 정합니다.
2. 데이터 사이트에서 데이터를 하나 찾아, 탭 **Ⅰ 기록하기**의 화면 다섯 개를 차례로 채웁니다. **자동 저장**됩니다.
3. 다 쓰면 **Ⅱ 마무리 → 📄 내 활동지 → [제출하기]**. 공용 컴퓨터라면 꼭 **[나가기]** 를 누릅니다.

## 선생님이 쓰는 시트 메뉴 여덟 가지

| 메뉴 | 하는 일 |
|---|---|
| ① 시트 준비하기 | 시트 네 장을 만든다 (처음 한 번) |
| ② 현황 요약 보기 | 인원·제출·평균 진행률, **평균이 절반에 못 미친 활동에 ⚠**, 칸별로 몇 명이 기준을 넘겼나 |
| ③ 고른 줄의 학생 답 자세히 보기 | 「제출 현황」에서 학생 줄을 고르고 누르면 서술 원문 전부 |
| ④ 미제출 학생 보기 | 아직 안 낸 학생과 진행률 |
| ⑤ **우리 반이 모은 데이터 한눈에 보기** | 관심 분야·형태 분포 막대 + **학생별 데이터 이름·기관·링크 목록** (링크를 눌러 확인) |
| ⑥ 제출 마감하기 / 다시 열기 | 마감해도 작성과 자동 저장은 계속된다 |
| ⑦ 비밀번호 초기화 | 잊은 학생용. **작성 내용과 점수는 그대로 남는다** |
| ⑧ 이 앱 정보 | 진행률 계산 방법 등 |

### 시트 네 장

| 시트 | 무엇이 들어 있나 |
|---|---|
| **제출 현황** | 채점용. 학생 1명 = 1줄, 32열 (메타 16 + 서술 13 + 활동 3) |
| 작성 중(임시 저장) | 이어 쓰기용 원본(JSON) |
| 제출 기록(백업) | 제출할 때마다 한 줄씩 쌓인다 — **제출 시점의 원문** |
| 계정(비밀번호) | 숨김. 비밀번호는 솔트+SHA-256 해시로만 저장되어 **선생님도 볼 수 없습니다** |

> **⑦-3 속성 표는 정형 데이터를 고른 학생에게만 나옵니다.** 다른 형태를 고른 학생은
> 이 칸이 비어 있는 것이 정상이고, 진행률 분모에서도 빠져 100%가 될 수 있습니다.
> 「현황 요약」의 ⑦-3 줄도 해당되는 학생만 세어 보여 줍니다.

> **「제출 후 수정」 열**을 보세요. 제출한 뒤에 고친 학생이면 그 시각이 적힙니다.
> 제출 시점의 원문은 「제출 기록(백업)」에 그대로 남아 있습니다.

## 개인정보

* **학번과 이름만** 씁니다. 그 밖의 개인정보는 받지 않습니다.
* 비밀번호는 알아볼 수 없는 형태(솔트+SHA-256 해시)로만 저장됩니다.
* 「우리 반이 모은 데이터」는 이름 없이 개수만 셉니다.
  적은 학생이 **세 명보다 적으면 열리지 않습니다** (누가 무엇을 골랐는지 드러나므로).
* 로그인 정보는 그 브라우저의 `sessionStorage` 에만 담기고, **[나가기]** 를 누르면
  그 컴퓨터에 남은 작성 기록까지 함께 지워집니다(컴퓨터실 대비).

## 한 차시가 아니라 두 차시로 나누고 싶다면

`src/Code.gs` 맨 위 **`COURSE`** 한 곳만 고치면 됩니다.
`screens` 에서 화면을 빼면 그 화면이 **잠기고**(탭·알약에서 사라지고 주소로도 못 들어감),
진행률의 분모도 그만큼 줄어 **범위만 다 하면 100%** 가 됩니다.
시트 열 구성은 그대로라 나중에 범위를 넓히면 예전 기록이 그대로 이어집니다.

```js
var COURSE = {
  name: '1차시 — 데이터 찾아 기록하기',
  screens: ['interest', 'source', 'reason', 'report'],   // 화면 넷만 연다
  fields:  ['interest', 'data_name', 'provider', 'source_url', 'license', 'why'],
  acts:    ['site-match']
};
```

⚠ `report` 를 빼면 **제출 단추가 사라집니다.**
⚠ `screens` 를 고치면 `fields`·`acts` 도 함께 고쳐야 합니다 — 어긋나면 `npm test` 가 잡습니다.
